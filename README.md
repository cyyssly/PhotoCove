# PhotoCove — 本地摄影作品展示站

纯静态单页应用：作品集（瀑布流）/ 时间轴 / 相册集 / Lightbox 大图浏览，EXIF 信息展示，暗色/亮色主题。
无需安装任何依赖，无需本地服务，**整个文件夹拷到任何电脑都能用**。

## 使用

1. 双击 `index.html`（推荐用 **Microsoft Edge** 或 **Chrome** 打开，其他浏览器不支持）
2. 进入「设置」→「＋ 添加图片库目录」，选择存放照片的文件夹（可添加多个）；新添加的目录会自动扫描一次
3. 扫描完成后回到「作品集 / 时间轴 / 相册集」浏览

### 日常使用

- 打开页面直接显示上次扫描的结果，**不做任何自动扫描**（点授权按钮也只是恢复权限，不会触发扫描）；需要更新时到「设置 → 图片库目录」点对应目录的「扫描」按钮，或用「维护 → 重新扫描」全量检查
- **扫描只读文件信息与分辨率**（解析文件头，不解码像素），几万张也是秒级完成；扫描期间右下角浮卡显示进度，随时可点「取消」，已扫描部分正常入库
- **缩略图按需生成**：浏览到哪张才解码哪张（瀑布流/时间轴滚动进入视口时自动生成，打开大图时生成高清预览），生成后缓存起来，第二次访问立即显示
- **分批加载**：作品集/时间轴/相册详情每次只渲染 36 张，滚动到底部自动加载下一批（也可点「加载更多」）。几万张照片也能秒开，不会一次性建几万个节点卡死页面；窗口缩放时已加载部分会重新分列，不影响已加载进度
- 原图始终留在原目录，本站只生成缩略图和索引，不修改、不移动任何原文件
- 点击图片进入大图浏览：`←` `→` 键或滑动切换，`Esc` 关闭；大图模式下自动显示器材与拍摄参数（机身/镜头/焦段/光圈/快门/ISO）
- 拍摄时间取自 EXIF，无效时间自动过滤（部分工具会写出 1899 年之类的畸形时间戳，宁缺勿错）

### 设置页说明

| 项目 | 说明 |
|---|---|
| 使用须知 | 列出浏览器兼容性、授权机制、RAW 策略等全部限制条件 |
| 外观 | 暗色（默认）/ 亮色主题切换 |

### 照片显示空白怎么办

按顺序看这三处，基本能定位：

1. **先看授权**：设置页「图片库目录」上方有一条常驻的授权状态栏。
   - 显示「有 N 个目录未授权」时，点它右边的 **「授权全部目录」**（浏览器会逐个弹询问框，全部点「允许」）
   - 也可以点单个目录右侧的 **「授权」** 按钮逐个处理
   - 未授权时照片无法解码，占位块显示「需要目录授权」，顶栏「设置」上还有一个提示点
   - 若点了授权**完全没有弹出询问框**，说明目录句柄已失效（目录被改名/移动/清理过浏览器数据），
     点该目录的「移除」再重新添加即可（原图不受影响）
2. **占位块上的文字**：
   - 「需要目录授权」→ 按上一步授权，页面会自动重试并重新加载
   - 「加载失败 · 点击重试」/「加载超时 · 点击重试」→ 单张文件问题（损坏、格式不支持如 HEIC），点一下重试；反复失败说明该文件本身解不开
   - 「RAW」→ 该文件是 RAW 且 RAW 支持未开启
3. **设置 → 维护 → 存储状态**：看「缩略图缓存」是否接近「照片记录」数、「待生成 / 失败」是否接近 0。
   明显偏少说明缩略图没生成成功，通常是目录未授权或磁盘空间不足；「当前占用」过小也印证了这一点
4. **占用异常大**（远大于照片数应有的体积）时，可「清空本地索引」后重新扫描，回收旧缓存

> 为什么会出现「记录说已缓存、实际没有图」：早期版本把「写库成功」当成理所当然，
> 存储配额写满时异常被静默吞掉，状态却照样写成已缓存，于是视图认定无需再生成，照片永久空白。

## 免授权提示（推荐）

浏览器不把这类权限长期保存：**完全退出浏览器**后再打开需要重新授权（按 F5 刷新页面不会重置，也不需要重新授权）。任何时候想确认当前状态，点设置页授权条上的「重新检查」。想跳过：

> Edge 菜单 →「应用」→「将此站点作为应用安装」，生成桌面图标；安装为应用后授权**永久记住**，双击图标直接进入。

## 数据存在哪里

网站本身不保存任何数据，所有索引和缩略图都在**浏览器的 IndexedDB** 里（库名 `photo-gallery`），
与项目文件夹无关。所以各种操作的影响是这样的：

| 操作 | 索引 / 缩略图缓存 | 原图 |
| --- | --- | --- |
| 项目文件夹改名、挪到别的盘 | 保留 | 不受影响 |
| 按 F5 刷新页面 | 保留 | 不受影响 |
| 浏览器「清除缓存的图片和文件」 | **保留**（IndexedDB 不属于 HTTP 缓存） | 不受影响 |
| 浏览器「清除 Cookie 及其他网站数据」 | **全部丢失**，需重新扫描 | 不受影响 |
| 换浏览器 / 换浏览器用户配置 / 系统重装 | 全部丢失 | 不受影响 |
| 磁盘空间极度紧张 | 尽力保留（已申请持久化存储，见下） | 不受影响 |

**任何情况下原图都不会被动到**：本站对照片目录只读，从不写入、移动或删除任何文件。
清理数据后的恢复动作只有三步：重新添加图片库目录 → 扫描 → 滚动浏览时重新生成缩略图。

启动时会调用 `navigator.storage.persist()` 申请「持久化存储」，获批后浏览器不会在磁盘紧张时
自动回收本站数据。批不批由浏览器决定（安装为应用、经常访问、加过书签更容易通过），
当前状态在「设置 → 维护 → 存储状态」的「存储保护」一行可以直接看到。

## 迁移到其他电脑

1. 把整个 `PhotoCove` 文件夹拷过去（U 盘、网盘均可）
2. 目标电脑用 Edge/Chrome 双击打开 `index.html`
3. 重新添加图片库目录（如果照片目录路径不同）

注意：缩略图索引存在**浏览器本地**，不随文件夹迁移，新机器首次打开会重新扫描一次。

反过来也成立：**改文件夹名、把项目挪到别的盘，索引和缓存都不会丢**（它们跟浏览器绑定，与项目路径无关），只需要重新授权一次图片库目录。

## 桌面版（Electron）

网页版受浏览器限制的地方，桌面版都消掉了。**同一份 `index.html`**，套了一层壳。

| 限制 | 网页版 | 桌面版 |
|---|---|---|
| 拿到绝对路径 | 拿不到，要手填一次 | 选目录即知道 |
| 每次启动重新授权 | 需要 | 不需要 |
| 浏览器清缓存导致索引丢失 | 会 | 不会，存在程序目录 |
| 唤起 GPSStamp | 自定义协议 + 「是否打开」确认 | 直接启动，带 `--missing-only` |
| 关掉页面就停 | 是 | 窗口在就能继续 |

### 启动

```bat
npm install          :: 只需一次
启动 PhotoCove.bat    :: 之后双击这个
```

也可以在命令行 `npm start`。`npm run selftest` 跑端到端自测（需要传 `--dir` 指向一个有照片的文件夹）。

### 数据在哪

`data\`（程序目录下）。索引与缩略图都在这里，整个文件夹拷走就跟着走。
只有程序目录只写时（例如放进 Program Files），才会退回系统的 `%APPDATA%\PhotoCove`。

### 实现要点

- `app://cove/` 承载页面，`covefile://local/?p=<路径>` 承载原图。不用 `file://`：它没有稳定 origin，IndexedDB 与相对路径都会被限制。
- 原图由协议层流式返回，不进 JS 堆；`<img src="covefile://…">` 直接由 Chromium 解码。
- 扫描阶段只读文件开头 512KB（`readHead`）解析尺寸与 EXIF，为的是不把整个图库读一遍。
  增量比对用的 `size` / `mtime` 来自 `fs.stat`，不是「读到的字节数」。
- `preload.js` 只暴露白名单方法，页面没有 `require`、没有 `ipcMain`，也读不到任意路径以外的文件。

### 已知限制

- HEIC 缩略图仍然不行：Chromium 内核不解 HEIC，Electron 也一样，除非引入 libheif。
- 未打包时依赖 `node_modules`（357 MB），打包成绿色目录属于下一步。
- 首次扫描仍需为每张照片读一段文件头，两万张的量级下耗时以分钟计，之后都走增量。

## 技术说明

- **文件访问收口在适配层**：`scanner.js` / `app.js` 不再直接调用 File System Access API，也不持有目录句柄。选目录、递归枚举、读文件、问权限这四件事统一走 `PLATFORM`——`js/platform/api.js` 只定契约，`js/platform/web.js` 给浏览器实现。好处是将来套 Electron / Tauri 外壳时，只需新增 `platform/desktop.js`，把同样几个方法换成 `fs` 调用，业务代码一行不用改
- **元数据与图片分开存**：`photos` 只放路径/时间/EXIF/尺寸等纯文本字段（几万条也只有几 MB），缩略图和预览 Blob 单独放在 `assets`，按需单条读取。这样打开页面时不会把整个图库的二进制一次性搬进内存（旧做法在几万张时会直接卡死）
- **两段式处理**：扫描阶段只做「枚举 + 文件信息 + 分辨率 + EXIF」，分辨率通过解析 JPEG SOF / PNG IHDR / WebP VP8X 等文件头得到，不解码像素；缩略图与预览在浏览时按需生成（解码并发上限 3，生成后写回 IndexedDB，并在内存里保留最近 400 张的 LRU 缓存）
- **解码即缩放**：生成缩略图时用 `createImageBitmap(src, { resizeWidth, resizeHeight })` 让浏览器在解码阶段直接降采样（JPEG 走 DCT 缩放），比「全尺寸解码再缩」快数倍、内存低一个量级
- 展示图与 EXIF 来自图片自带的元数据与机内预览，**不做 RAW 原始数据解码**（速度快，效果即相机直出观感）；如需编辑级 RAW 解码需另行方案
- 缩略图长边 640px（网格），WebP 格式，单张约 30–80 KB
- **大图按屏幕分辨率自适应**：读取当前屏幕分辨率（CSS 像素 × devicePixelRatio，夹在 1280–4096 之间），长边**不超过**屏幕长边的照片直接显示原图（零转换、最高画质）；只有超过的才生成一张「屏幕长边」大小的 WebP 预览并缓存，避免超大图反复解码拖慢浏览
- 增量比对按「修改时间 + 文件大小」，未变化的文件完全跳过读取
- **失败状态一律不落库**：目录未授权、解码失败、解码超时都只在内存里记一笔（供占位块提示与「点击重试」），下次打开页面或授权恢复后自动重试。只有「RAW 支持未开启」是合法的永久状态——早期版本把临时失败写成永久不可用并落库，会导致照片即使授权了也永远空白，v5 起已修正并会自动复位存量脏状态
- 单张解码任务有 20 秒超时，避免个别文件卡住并发槽位导致整个缩略图队列停摆
- **缓存写入失败不再被静默吞掉**：写 IndexedDB 失败（多为配额耗尽）时，状态不会被标成「已缓存」，并在「存储状态」里提示；启动时还会请求持久化存储，减少浏览器回收数据导致的空白
- **失败状态一律不落库**：解码失败、超时、授权缺失都只记在内存，刷新页面或重新滚动就会自动重试，不存在「点修复才能恢复」的死状态
- 脚本异常不再只躺在控制台：会以页头提示条显示，避免「点了没反应」无从排查
- **分批渲染**：每批 36 张，页脚哨兵进入视口（提前 700px）时追加下一批；瀑布流由 JS 维护等宽列并按预估高度投放，避免 CSS `column-count` 追加时整体重排导致图片跳位
- 浏览器缓存了旧脚本时界面行为会和说明不符，按 `Ctrl + F5` 强制刷新即可（设置页底部显示当前程序版本）
